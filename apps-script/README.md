# NFL Picks backend (Google Apps Script)

Backend for `picks.html`. Data lives in the picks spreadsheet:
https://docs.google.com/spreadsheets/d/17WYua_IqVvIcLj6ZhfOeYM01d7TAq4imrS2Iv_BRSTI/edit

Lines and scores come from ESPN's public scoreboard (which includes DraftKings spreads), so no API key is needed.

## How picks work

Each player enters a number for each game: the home team's spread as they see it. That number is compared to the DraftKings line (`home_spread`, frozen when first recorded):

| Player's number vs line | Player's side |
|---|---|
| lower (e.g. -2 vs +2.5) | home team at the line |
| higher | away team at the line |
| equal | no pick |

The side is then graded W/L/P against the spread. The page hides the line until you've submitted a game (or it has kicked off), so picks are made blind. Submitted picks are final, and anything unpicked locks at kickoff. The line is hidden on the page only: `action=games` still returns it.

## Tabs

The script only reads and writes tabs whose names start with `TAB_PREFIX` (currently `TEST_`, at the top of `Code.gs`). Existing tabs like the Week 4 sheet and `TestSheet` are never touched.

- `TEST_Games`: week, game_id, kickoff_utc, away_team, home_team, home_spread, away_score, home_score, status, ats_winner
- `TEST_Picks`: submitted_at, user, week, game_id, guess, pick (one row per user and game; picks are final, so the server rejects a second submission for the same game)
- `TEST_Users`: user_slug, display_name
- `TEST_Stats`: generated by the script (season and per-week W/L/P per user). Don't edit it by hand.

## Setup

1. **Open the script editor.** In the spreadsheet: Extensions > Apps Script.
2. **Paste the code.** Replace the contents of `Code.gs` with this folder's `Code.gs` and save.
3. **Create the tabs.** Pick `setupSheet` in the function dropdown and click Run. Approve the permissions prompt the first time (Advanced > Go to project).
4. **Add users.** Edit the list in `seedUsers()` if needed, then run `seedUsers`.
5. **Load games.** Run `fetchOdds` to pull this week's and next week's games and lines. Then run `rebuildStats` so the leaderboard lists everyone.
6. **Install triggers.** Run `setupTriggers`. It replaces any existing `fetchOdds`/`fetchResults` triggers with:
   - `fetchOdds`: Wednesdays 10am ET
   - `fetchResults`: daily 9am ET, plus 1–2am ET on Friday, Monday and Tuesday (after the Thursday, Sunday and Monday night games)
7. **Deploy.** Deploy > New deployment > type **Web app**. Set Execute as: **Me** and Who has access: **Anyone**. Click Deploy and copy the Web app URL (ends in `/exec`).
8. **Configure the frontend.** In `picks.html`, set `const SCRIPT_URL = '<that URL>';`, then commit and push.

Each player's link is `https://aj3189.github.io/picks?user=<slug>`, e.g. `?user=andrew`.

### After changing `Code.gs`

Deploy > Manage deployments > edit (pencil) > Version: **New version** > Deploy. This keeps the same URL. A "New deployment" would create a new URL.

## Going live (dropping the `TEST_` prefix)

Set `TAB_PREFIX = ''` and redeploy, then run `setupSheet`, `seedUsers` and `fetchOdds` again. They create `Games`, `Picks`, `Users` and `Stats`. Make sure no existing tab already uses one of those names.

## Notes

- **Line freeze:** a game's `home_spread` is written only while it's blank and before kickoff. After that the script never changes it. To override a line, edit the cell by hand.
- **Missing line:** if ESPN has no line when `fetchOdds` runs, the next `fetchResults` run fills it in. Until then that game can't be picked.
- **Failures:** if ESPN is down or returns something unexpected, the error is logged (Executions panel) and nothing is written.
- **ESPN hosts:** `site.api.espn.com` returns 403 to Apps Script, so the script uses the `site.web.api.espn.com` mirror first and only falls back to the original. If both start failing, check `ESPN_URLS` in `Code.gs`.
- **Season:** this covers the regular season only (`SEASON_TYPE = 2`). Weeks are not tagged by season, so start fresh tabs each year.
- **No login:** anyone who knows a player's slug can submit as them or read their picks. Good enough for friends, not for money.

## Endpoints

- `GET ?action=games[&week=N]`: `{week, weeks, games}`. If `week` is omitted, returns the current week (the earliest week with an unfinished game).
- `GET ?action=picks&user=X&week=N`: `{picks: [{game_id, guess, pick, result}]}`. `result` is `W`, `L`, `P` or empty.
- `GET ?action=stats`: `{stats: [...]}`, the rows of the Stats tab.
- `POST` with a `text/plain` JSON body `{user, week, picks: [{game_id, guess}]}`. Games already picked by that user are rejected as `Already submitted`. Returns `{saved, rejected: [{game_id, reason}]}`.
